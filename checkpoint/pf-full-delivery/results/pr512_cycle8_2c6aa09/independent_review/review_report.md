## Findings

1. **P2 — #2 residual window: ACTIVE persisted before the demotion** — `core/microstake_sim_port.py:348-354` vs `core/microstake_safe.py:548-556`. Sequence is: port op → final snapshot fails (flag only) → coordinator `_activate()` saves `phase=ACTIVE, reservation_held=False` and releases the reservation → *then* the executor demotes to AMBIGUOUS. A crash between `_activate` and `_demote_unpersisted_active` leaves the exact Codex scenario: saga ACTIVE, reservation released, reload source stale, `pending_refs()` empty so `recover_pending()` never touches it. **CONFIRMED** with `review_c8/test_window_f2.py` (crash injected in `_demote_unpersisted_active`: `saga ACTIVE held False, pending_refs [], db.simulation_state None`). Impact is SIM-only (LIVE has no adapter), so no real money; the fix narrows the window from "always" to "a few statements", which is a genuine improvement but not a closure. Fix shape: let the coordinator see the port flag *before* activating — e.g. in `_activate` (or just before it in `execute`/`recover`) check `getattr(self.exchange, "last_snapshot_persisted", True)` and save AMBIGUOUS/held instead of ACTIVE; the executor-level demotion then becomes a belt-and-braces path.

2. **P2 (gap, same family as #2) — unpersisted final snapshot on a ROLLED_BACK saga is not demoted** — `core/microstake_sim_port.py:296-304` (`cancel_all_remaining` → `_snapshot()` result ignored) and `:351` (demotion only for `SUCCESS`/`ACTIVE`). After a restart the SIM broker reloads a stub still open while the saga is terminal (`ROLLED_BACK` is excluded from `pending_refs`). It is caught downstream by F018/ghost detection (exchange order without DB row → ghost cancel), so fail-closed in practice. PLAUSIBLE (by inspection, not run). Fix shape: same port-flag check for any terminal phase whose last op's snapshot failed → AMBIGUOUS held; or document as accepted since the ghost path covers it.
